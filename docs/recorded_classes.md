# Recorded classes

**Agent-facing. Not a user page** — it is in `mkdocs.yml`'s `exclude_docs`.

Each row is a bug class this repository has already paid for: a rule, plus the guard that
enforces it. **Re-breaking one of these is a regression with a history, not a new bug.**

Read this when a sweep turns up a shape you recognise, and when writing a guard — step 2 of
*Fixing a bug means fixing its class* (`CLAUDE.md`) is "derive a searchable signature and sweep",
and this is the list of signatures somebody has already derived.

The **guard's own module docstring is the canonical write-up** — it cannot drift from the thing
enforcing it, where a second copy in prose can. A row here is the index into those docstrings.
Adding a row is step 6 of that procedure; removing one is step 5, and happens in the change that
made the class impossible.

**Shown able to fail** is the evidence that the guard still guards: the bug put back in `detail/`
(a fix reverted, a forbidden call restored), and what the cited guard did — each run as
`pytest -q <guard>`, with the mutation checked to have changed the file, and the file restored to
green afterwards. The column was filled by the 2026-09-29 sweep (#535), which found **97 live,
0 retired**: no row's mechanism has left the package. Four guards were green against their own
bug and were fixed in that change, and the eleven partial gaps it found were closed in #539 — a
cell reading *was **green*** names the mutation that used to pass. **Gap** marks a real site of the
class that the guard does not reach; **Deliberately not covered** marks one left on purpose, with
the reason. A row added later fills this column the same way — a guard is kept because it failed, not
because it exists. A row is retired only when its mechanism is gone from `detail/`; a guard that
cannot fail on a live mechanism is fixed, not deleted, since deleting it leaves the class
unguarded.

**Retired** (step 5), 2026-11-09 on `main`, when the montage window and its page machinery left
`detail/api/clip_montage.py`: *a shared resource closed from a view that does not own it* — the
window's pages were `ClusterMontage.subset`s over one shared state; with `subset` gone every
montage owns its own state and its `close()` is the only one, so the class cannot be written
there. *A geometry rule written twice, once per surface* — the window's picture and hit test
were the second surface beside an export's frame; only the export draws the grid now. Their
tests went with the mechanism, or stay as ordinary tests of the export.

**Live again**, 2026-11-10: the merge of `main` into remote-detail kept remote-detail's montage
engine, and `ClusterMontage.subset` with it: **Export clips…** (`gui/export_clips.py`) and
`api/montage_export.py` draw their preview and their plan through subsets of one root montage.
The first of those two classes can be written there again, and has no row and no guard on this
branch: a **gap**, to be closed with a row when its guard is written. The second stays retired:
the window's grid, selection marks and hit test (`grid_columns`, `tile_size`, `hit_tile`) left the
engine with the draw-ahead (`draw_ahead`, `DrawnAhead`) when nothing live called them.

**Retired** (step 5), 2026-11-10, when the node cache's size floor and the tree's *Preview
clips…* left `detail/`: *a picture budget read as a reachability rule* — the cache listed members
only for nodes over its floor, and *Preview clips…* read "not listed" as "nothing to play",
greying 461 of 599 nodes of a real run. Every node now lists every clip (`DESIGN_PLAN.md` §22
*Every node's clips*), so there is no budget to misread. Its GUI tests went with the tree item;
`tests/api/test_node_members.py` stays as an ordinary test of the order.

This table lived in `CLAUDE.md` until it reached 41,146 characters — a quarter of a file loaded
into every session — which is the thing `CLAUDE.md`'s own step 6 tells you not to do: *"Keep the
entry here to a rule and a pointer; this file is loaded every session and is for operative rules,
not case history."*
